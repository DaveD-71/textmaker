# Autotextstyle — Markdown ↔ DOCX textbook tools

## Purpose

- Convert Markdown textbook content into a professionally styled Microsoft Word (`.docx`) document.
- Convert DOCX back into unit-level Markdown with extracted assets.
- Provide a CLI workflow and a reusable `reference.docx` style file for consistent typography, A4 sizing, headers/footers, and an autogenerated Table of Contents.

## Prerequisites

- Python 3.9+ installed
- Pandoc binary installed and available on PATH (<https://pandoc.org/installing.html>)
- Optional: Microsoft Office/Word to open the generated `.docx` or LibreOffice.

## Quick start (PowerShell)

```powershell
# create and activate venv
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# install Python dependencies
pip install -r requirements.txt

# generate a style reference document (creates reference.docx)
python .\scripts\generate_reference_docx.py --out reference.docx

# convert a markdown file (or multiple) to docx using pandoc and the reference
python .\scripts\cli.py --input "..\path\to\your\file.md" --output "MyBook.docx"
```

## Generate `reference.docx` (options)

```powershell
# write reference.docx to the current folder (default)
python .\scripts\generate_reference_docx.py

# choose a custom output path
python .\scripts\generate_reference_docx.py --out ".\Writing textbook\Advanced\reference.docx"

# show all flags
python .\scripts\generate_reference_docx.py --help
```

- `--out <path>`: output path for the generated reference file (default `reference.docx`).
- `-h, --help`: show the built-in help for the generator script.

## Markdown → DOCX CLI usage and options

```powershell
python .\scripts\cli.py --input <file-or-folder> `
  --output output.docx `
  --reference reference.docx `
  --toc `
  --toc-depth 2
```

- `--input` (required): a single `.md` file or a folder of `.md` files. Folders are merged in sorted order; a section break is inserted between files.
- `--output`: DOCX to write (default `output.docx`).
- `--reference`: reference DOCX to apply styles (default `reference.docx`; regenerate with `scripts/generate_reference_docx.py`).
- `--toc`: include an autogenerated Table of Contents.
- `--toc-depth`: TOC heading depth (default `2`).

## Post-processing behavior

- If `--toc` is used, the generated DOCX gets a next-page section after the TOC and restarts page numbering at 1 for the content.
- Each Heading 1 unit starts on its own page/section.
- When merging multiple markdown files, they are concatenated in sorted order.

## Reverse conversion: DOCX → Markdown (units) + assets + styles

```powershell
python .\scripts\docx_to_markdown.py `
  --input ".\reference.docx" `
  --output-dir ".\docx_export" `
  --assets-dir "assets" `
  --unit-heading-level 1 `
  --reference-out ".\reference-from-source.docx" `
  --preserve-headers
```

Default behavior (no extra flags required):
- Output folder: `<input basename> out` (created next to the input DOCX).
- Markdown output folder: `.md` inside the output folder.
- Assets folder: `assets` inside the output folder.
- Reference DOCX: `reference.docx` inside the output folder.
- Split level: Heading 1 (`--unit-heading-level 1`).

Options:
- `--input` (required): source DOCX to convert.
- `--output-dir`: output folder (default: `<input basename> out`).
- `--assets-dir`: assets folder (relative to output dir by default, or absolute).
- `--unit-heading-level`: heading level to split on (default `1`).
- `--reference-out`: path for reference DOCX (default: `<output-dir>\reference.docx`).
- `--preserve-headers`: keep headers/footers in the reference DOCX.
- `--keep-temp-md`: keep `_full.md` and `_preprocessed.docx` intermediates.
- `--pandoc-bin`: override pandoc executable name/path.

Conversion details:
- Pandoc converts the DOCX to a single `_full.md`, then the script splits it into numbered files
  (`01-<slug>.md`, `02-<slug>.md`, ...) under the `.md` subfolder.
- Headings are detected by markdown syntax (e.g., `#` for level 1). If the DOCX uses Heading 2/3 styles, you may need `--unit-heading-level 2` or `3`.
- Embedded images are extracted via `--extract-media` and referenced in the markdown.
- Tables may be emitted as HTML when they are too complex for pipe-table syntax.
- Word shapes are not preserved by pandoc; the preprocessor inserts placeholders using alt text where possible.

Sentinel markers:
- Preprocess inserts markers like `[[PAGEBREAK]]`, `[[SECTIONBREAK]]`, `[[LINEBREAK]]`.
- Pandoc may escape them (e.g., `\[\[PAGEBREAK\]\]`), and post-processing restores them to `\pagebreak` or `<br>`.

## Split DOCX into unit files (docx → docx)

The `split_docx_units.py` utility splits a DOCX into per-unit DOCX files based on simple unit markers.

```powershell
# default output folder: "<input basename> out"
python .\scripts\split_docx_units.py ".\path\to\source.docx"

# optional custom output folder
python .\scripts\split_docx_units.py ".\path\to\source.docx" ".\path\to\output-folder"
```

How it decides split points:
- It scans each paragraph/table block for lines that match either:
  - `^\s*(\d+)\s*:\s*(.+)$` (e.g., `3: Unit Title`), or
  - `^\s*(\d+)\s*$` followed by a non-empty title line (e.g., `3` then `Unit Title`).
- Each match starts a new unit. The unit runs until the next unit marker.
- If the first unit marker is not at the start of the document, the first unit includes everything before it.

Output behavior:
- Creates an extension subfolder inside the output directory (e.g., `.docx`, `.docm`, `.dotx`, `.dotm`).
- Creates one folder per unit inside the extension subfolder, named `Unit <number> - <title>`.
- Writes a DOCX into each folder with the same name.
- Removes images from unit outputs.
- Unit titles are sanitized to ASCII‑safe filenames.
