### Shared Design Direction

Both process-improvement slide sets should use a restrained operational briefing style: clean white background, strong takeaway titles, limited text, and simple workflow visuals. The main distinction should be context and visual language:

- Business model: operations-control tone; structured, precise, slightly more corporate; use neutral blue/gray with one accent color.
- Government model: public-service/admin tone; warmer, simpler, more service-facing; use neutral gray/green or blue/teal, no official symbols.

Both should avoid decorative images. The strongest visual type is a before/after workflow, supported by one small evidence snapshot and one simple implementation timeline.

### Model 1: Business Client - Reducing Import Document Handoff Delays

Recommended number of slides: **6**

| Slide | Takeaway Title | Exact Concise Slide Text | Speaker-Support Role | Visual Need |
|---|---|---|---|---|
| 1 | Approve a Four-Week Workflow Pilot | Decision today: pilot the shared exception log. Confirm the checkpoint owner. Review delay and rework after four weeks. | Sets purpose and decision request. | No visual beyond layout; optional small decision icon. |
| 2 | Handoff Notes Are Spread Across Three Places | Email. Spreadsheet. Short messages. Ownership is unclear before the cutoff preparation window. | Shows the current problem clearly. | Current-state process diagram. |
| 3 | Most Delays Involve Unclear Handoff Notes | 38 late handoffs. 61% linked to unclear notes. 22 minutes average rework. | Gives enough evidence without making the deck data-heavy. | Evidence snapshot, not full chart. Three-number panel. |
| 4 | One Shared Log Makes Ownership Visible Earlier | Required fields: issue, owner, next action. Fixed checkpoint before cutoff preparation. Control process unchanged. | Explains the recommendation. | Before/after workflow diagram. |
| 5 | The Pilot Is Limited and Controlled | Week 0: review fields. Weeks 1-4: daily checkpoint. End: review delay, rework, and feedback. | Makes the plan practical and reduces risk concerns. | Simple timeline. |
| 6 | The Request Is Approval, Ownership, and Review Criteria | Approve the pilot. Confirm the documentation lead. Agree the review measures. | Supports the close and final action request. | No visual beyond layout; optional three-part decision panel. |

Checklist notes:

- One message: each slide has one decision/problem/evidence/recommendation/plan/close role.
- Hierarchy: takeaway title carries the main point; body text stays short.
- Spacing/readability: avoid more than three short text blocks per slide.
- Accessibility: workflow labels must not depend on color alone; use labels such as `Current`, `Pilot`, `Owner`, `Next action`.
- Avoid script-like text: the script explains cause, risk, and confidentiality; slides only show prompts and evidence.

Shared design rules from agent:

- Use **takeaway titles**, not topic titles.
- Keep visible text to short labels and decision/action phrases.
- Do not put script sentences on slides.
- Use data only where the script depends on it: Slide 2 in both models.
- Use visual structure where the script explains a process: dashboard mockup for business, service-flow diagram for government.
- Use timelines only for rollout slides.
- Keep backup details out of the slide set: confidentiality rules, staffing details, field lists, and Q&A limits belong in notes or backup material.

## Agent 3: Project Results Briefing Models

### Shared Design Direction

These two sets should use an evidence-review style: calm, sparse, data-led, and decision-focused. They should be visually different from process models, which should emphasize workflow, and launch models, which should emphasize rollout/timeline. For results briefings, the signature visual pattern should be: one clear number, one simple comparison, one limitation, one recommendation.

Recommended structure for each model: **5 live slides + 1 backup slide**. The backup slide should not be part of the main flow unless the audience asks about methodology, workload, or limits.

### Model 1: Business Client - Exception Resolution Pilot

Style direction: professional operations-review pack. White or very light background, dark blue/charcoal text, one muted accent color for the pilot result. Use simple bars, small evidence cards, and a controlled-expansion decision panel. Avoid decorative trade/import imagery.

| Slide | Title | Exact Slide Text | Speaker-Support Role | Visual Need |
|---|---|---|---|---|
| 1 | Approve a Controlled Expansion of the Exception Resolution Pilot | Decision today: expand to two more desks for six weeks / Controls: morning log check + duplicate-entry owner | Opens with the decision and prevents the presentation from becoming only a report. | No visual beyond clean decision layout; optional small decision icon. |
| 2 | The Pilot Targeted Unclear Exception Ownership | Problem: exceptions were handled across separate messages / Change: shared exception log + fixed daily checkpoint / Goal: fewer late handoffs and less rework | Explains why the pilot existed and defines the operational problem. | Simple before/after process diagram, not detailed workflow. |
| 3 | Late Handoffs Fell from 38 to 27 | Late document handoffs: 38 -> 27 / Rework time: 22 min -> 16 min / Ownership clearer: 82% of users | Supports the main evidence claim. Presenter explains the numbers aloud. | Simple paired bar chart plus one evidence card. Needs fictional-data note. |

Important design note from agent:

## Consolidated Observations

- All six model slide sets should use 6 slides.
- The results sets should treat slide 6 as a backup slide, not a live main-flow slide.
- Slide titles should be takeaway titles, not topic labels.
- Slide text should be concise speaker support, not script text.
- Visual types should differ by model family:
  - Process improvement: workflow/process diagrams, evidence snapshots, limited timelines.
  - Launch: dashboard/service-flow visuals, benefit cards, rollout timelines.
  - Results: simple comparison charts, evidence cards, limitation/recommendation panels, backup tables.
- The current generated/model-slide PNGs should not be treated as approved references.
- Final rebuild should use deterministic slide layouts with editable text/shape/chart logic. AI imagery, if used at all, should be limited to non-text source art and should not render final slide text.
