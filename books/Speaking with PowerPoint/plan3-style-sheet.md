# Plan 3 Style Sheet

Prepared: 2026-08-12

Purpose: define the editorial, terminology, level, AI, accessibility, citation, file, and case rules for the Plan 3 rebuild before drafting begins.

## 1. Project Identity

Working series title: *Presentation Skills*

Use the old title *Speaking with PowerPoint* only when referring to the source textbook or legacy export files. Do not use PowerPoint as the organizing concept for the new course.

Preferred course description: business presentation skills with visuals.

Avoid these as course descriptions:
- PowerPoint textbook
- speech textbook
- slide design course
- AI presentation course
- public speaking course

## 2. Audience and Level

Target learners: adult B1-B2 business English learners, especially learners who present in international workplace settings.

Assume learners may be confident professionals but still developing English presentation control. Treat them as adults, not beginners.

Level control:
- Use clear business English.
- Prefer concrete verbs over abstract nominalizations.
- Keep instructions direct and task-oriented.
- Define specialist terms when first used.
- Avoid long chains of subordinate clauses in learner-facing task instructions.
- Do not simplify business ideas so far that the material feels childish.

## 3. Tier Voices

Use the existing tier voice guides as the base:

- Essentials: `books/Presentation Skills/canon/voice-E.md`
- Standard: `books/Presentation Skills/canon/voice-S.md`
- Long: `books/Presentation Skills/canon/voice-L.md`

Plan 3 application:
- Standard is the source of truth.
- Essentials compresses Standard into shorter, more direct instruction and fewer options.
- Long expands Standard with nuance, alternatives, stakeholder complexity, and deeper reflection.
- Do not let the tiers contradict each other on terminology, cases, sequence, or assessment principles.

## 4. Core Terminology

Use these terms consistently:

| Preferred Term | Use For | Avoid or Limit |
|---|---|---|
| presentation | General course object | speech, unless discussing spoken text specifically |
| talk | Informal reference to a presentation | speech as default |
| briefing | Short business presentation that informs or updates | speech |
| proposal | Presentation requesting approval or action | sales pitch unless it is actually sales |
| update | Status or progress presentation | report speech |
| visuals | Any visual support | PowerPoint as synonym |
| slides | Slide-based visual materials | Power Point, projected materials |
| deck | Business slide file, when natural | PowerPoint file as generic term |
| visual pack | Slides, documents, charts, and support visuals together | PowerPoint |
| presenter notes | Speaker notes or private notes | script, unless full script is intended |
| pre-read | Document sent before a meeting | handout before presentation, if vague |
| worksheet | Material used during a session | handout, if vague |
| leave-behind | Material sent or given after a presentation | handout, if vague |
| appendix or backup slides | Supporting detail used if needed | extra slides, if vague |
| screen share | Showing material in an online meeting | projected slides, for online context |
| dashboard walkthrough | Presenting data directly from a dashboard | PowerPoint presentation |

PowerPoint, Google Slides, Keynote, Canva, Figma Slides, Pitch, Gamma, PDFs, dashboards, and documents may be named only as examples where tool choice is being discussed. Do not list tools as a selling point or as a required workflow.

## 5. Presentation English Coverage

The language syllabus must be visible across lessons. Include learner-facing language for:

- stating purpose and audience relevance
- opening a presentation
- previewing structure
- moving to the next point
- referring back
- referring forward
- emphasizing a key point
- introducing visuals
- explaining charts and trends
- summarizing
- making recommendations
- closing with a decision or action
- clarifying questions
- answering directly
- deferring questions
- handling disagreement
- following up
- reflecting on performance
- handling technical problems
- managing screen-sharing transitions
- explaining audio, caption, or connection problems
- recovering timing
- moving to a backup file or follow-up document

Correct false or over-absolute rules from the source book. In particular:
- "At first" is not used for list sequencing, but it is not always wrong.
- "Then" is acceptable for sequence when used clearly.
- "Let's" can be collaborative, but it is not always precise for business recommendations.
- "That's all" is usually weak as a formal close, but do not present it as universally ungrammatical.
- "In charge of" is valid in many role contexts; teach the difference from "responsible for," "manage," "lead," and "take care of."

## 6. Japanese-Learner Notes

Include Japanese-learner notes where they solve a real presentation-English problem. Keep them brief and practical.

Useful topics:
- katakana-influenced pronunciation risks
- word stress and thought groups
- articles and plurals in slide text
- overly indirect conclusions
- over-scripted delivery
- sentence-by-sentence translation from Japanese
- direct but polite recommendation language

Avoid:
- stereotypes
- claims about all Japanese speakers
- advice that forbids bilingual planning
- replacing pronunciation work with vague "speak slowly" advice

Preferred preparation guidance: learners may plan ideas in the most efficient language, but they should draft, rehearse, and deliver natural English rather than translating sentence by sentence.

## 7. AI Policy

AI is critical-literacy content, not a promoted production workflow.

Allowed learner-facing uses:
- critique a flawed AI-generated opening, outline, slide, or visual
- identify generic language
- identify factual risk
- discuss confidentiality and company policy
- discuss copyright and licensing risk
- rewrite output into learner-owned English
- compare AI output with the course rubric

AI activities should use short flawed sample outputs supplied by the course. They should not use the learner's final presentation as AI source material, and they should not become a drafting workflow for assessed work.

Do not tell learners to:
- outsource their final message to AI
- read AI-generated text
- use AI to avoid developing English
- generate final slides without human review
- enter confidential company data into external tools

Required framing whenever AI appears:
- The learner remains responsible for accuracy, language, message, and delivery.
- AI output must be checked.
- Company policy comes first.
- The course goal is English development through presentation practice.
- Assessed message, slides/visuals, notes, rehearsal, delivery, and Q&A must be learner-owned.

## 8. Accessibility Rules

Accessibility is part of business quality and learner skill, not only a production QA issue.

Learner-facing accessibility points:
- readable text size
- sufficient contrast
- color not as the only signal
- clear chart labels
- short, meaningful slide titles
- simple visual hierarchy
- reduced cognitive load
- captions or transcript awareness for recorded material
- alt-text awareness for shared files
- inclusive delivery habits

Production rules:
- Every meaningful image needs alt text.
- Decorative images must be marked decorative in the asset register or notes.
- Charts must be understandable without color alone.
- PDF accessibility should receive the minimum available tool check plus manual review notes for anything the tool cannot verify.

## 9. Case and Data Rules

Use the three approved recurring cases:

1. Process improvement briefing
2. Product/service launch
3. Project results briefing

Case rules:
- Keep company and product names fictional unless using a verified real source.
- Label fictional data clearly.
- Use realistic but simple business situations.
- Avoid volatile, high-risk, or highly technical claims unless sourced.
- Do not reuse the old Ventura case as the main spine unless it is intentionally rebuilt and approved.
- Business-client examples should focus on finance/trading operations, reporting, workflow, client service, service quality, or control escalation; do not create trade recommendations, market predictions, client/account examples, or regulatory/legal advice.
- Government-agency examples should focus on administrative tasks, service delivery, reporting, coordination, process improvement, and service communication; do not drift into political advocacy, legislation, budget campaigning, or public-policy argument unless explicitly approved.

Data rules:
- Every real data claim needs a source.
- Every fictional chart needs a note that the data is fictional for practice.
- Charts should have takeaway titles.
- Do not use decorative data.

## 10. Visual and Asset Rules

Every final asset must have:
- file path
- source
- license status
- generated/original status
- alt text
- decorative flag
- caption, if needed
- lesson/tier use
- replacement rationale
- visual restriction check
- approval owner

Preferred asset types:
- editable diagrams
- simple original charts
- generated business mockups with clear rationale
- clean line icons
- screenshots only when necessary and current

Avoid:
- dated clip art
- repeated male-presenter silhouettes
- unreadable screenshot text
- generic stock-like business imagery
- tool UI screenshots that will date quickly

Generated-image inspection must check text accuracy, element count, label placement, no stray readable text, no logos/watermarks, no flags/seals/crests, representation requirements for people, and transparent-background quality where applicable. Existing Presentation Skills assets may be reused only after reapproval against Plan 3 restrictions.

Use the OpenAI image generation API only for custom business visuals where original assets are needed and licensing clarity matters. Do not add Canva or another external design workflow unless the user explicitly chooses it.

## 11. Tool-Neutral Workflow Rules

Teach tool choice by context:
- audience
- delivery mode
- collaboration needs
- data source
- visual complexity
- accessibility
- export and compatibility
- confidentiality
- company policy

Do not prescribe one tool or one file format. Slides, PDFs, documents, dashboards, worksheets, pre-reads, leave-behinds, and backup slides each have legitimate uses.

Preparation checklists should include:
- approved cloud location
- offline copy
- PDF fallback
- font/media/link checks
- venue or platform test
- presenter notes
- backup or appendix materials
- security policy

## 12. Assessment and Feedback Rules

Standard final rubric categories:
- message clarity
- audience fit
- structure
- evidence
- visual effectiveness
- spoken English
- delivery
- Q&A
- timing
- professionalism
- accessibility
- reflection

Separate formative peer feedback from formal assessment.

Q&A is required in Standard and Long. Essentials may use a shorter Q&A format, but it should not disappear entirely.

Assess English development and presentation effectiveness separately. A learner can have a strong message with language problems, or accurate language with weak audience fit; the rubric must make that visible.

## 13. Source and Citation Rules

Use official or stable sources for:
- tool capabilities
- accessibility guidance
- real business data
- 2026 workplace claims
- copyright or licensing guidance

Avoid detailed step-by-step software instructions unless verified close to publication. Interfaces change quickly.

In learner-facing materials, keep citations light. In teacher notes, asset registers, or source notes, record enough detail to verify the claim later.

## 14. Formatting and File Rules

Preferred file locations:
- planning and approval docs: `books/Speaking with PowerPoint/`
- final series source files: `books/Presentation Skills/`
- generated or final assets: `books/Presentation Skills/images/`
- temporary conversion output: system temp folder, not the repository

Markdown style:
- use ATX headings
- use sentence-style headings unless a file already has another convention
- use simple tables for matrices and checklists
- keep blank lines around headings and tables
- use ASCII punctuation unless existing content requires otherwise

Known cleanup items:
- remove any `:codex-annotation{...}` text from saved files
- use "QA and Acceptance," not "QA And Acceptance"
- use "AI use policy," not "AI-use policy"
- use "the OpenAI image generation API"
- use "license status," not "license/status"
